## 1. 设计目标与原则

### 1.1 五条原则

1. **单一真相源**：所有记忆只存在 PostgreSQL 一份。图是索引，不是第二份数据，不做双写。
2. **业务逻辑单点**：MCP、REST、后台任务共用同一个 `MemoryService`，传输层只做参数翻译。
3. **按变化频率分层**：慢变量（性格、规则）与快变量（最近事件）分开放，避免每轮重写高价值内容、破坏前缀缓存。
4. **预算硬约束**：任何注入上下文的路径都必须传预算，超限必须裁剪或报错，不允许"悄悄变长"。
5. **先够用，留出口**：首版不引入图数据库，但表结构与查询封装保留切换点（见 4.5）。

### 1.2 关键取舍一览

| 决策点 | 选择 | 放弃的方案 | 理由 |
|---|---|---|---|
| 存储 | PostgreSQL 单库 | Neo4j / 多库组合 | 需要中文全文、向量、事务、版本四合一；三跳内 CTE 够用 |
| 语言 | TypeScript（Node 22） | Python / Go | MCP 官方参考实现 + 前端生态同栈，一次构建 |
| 图查询 | 递归 CTE + 应用层 PPR | 图数据库原生算法 | 一跳 < 10ms 足够；PPR 在子图上跑，避免全图迭代 |
| 分层 | L1 / L1.5 / L2 / L3 | 纯摘要金字塔 | 快慢变量分离，保护前缀缓存 |
| 联想 | term × intent 二维倒排 + 图扩散 | 纯向量相似度 | 向量给不出"同一入口词的多条历史分支" |
| 传输 | HTTP 为主 + stdio 兼有 | 仅 HTTP | 桌面客户端普遍只支持 stdio |

## 2. 总体架构

```
                    ┌──────────────────┐
   Agent(本地) ────▶ │  MCP · stdio     │
                    ├──────────────────┤
   Agent(远程) ────▶ │  MCP · HTTP      │  POST /mcp  (Mcp-Session-Id)
                    ├──────────────────┤
   浏览器      ────▶ │  REST  /api/*    │──▶ 静态资源 /
                    └────────┬─────────┘
                             │
                    ┌────────▼─────────┐
                    │  MemoryService   │  recall / expand / write
                    │  （唯一业务层）   │  correct / forget / promote
                    └────────┬─────────┘
                    ┌────────┴─────────┐
             ┌──────▼──────┐    ┌──────▼────────┐
             │ PostgreSQL  │    │ Promotion     │
             │ + pgvector  │◀───│ Worker(异步)  │
             └─────────────┘    └───────────────┘
```

单进程部署：一个 Node 服务同时承载 MCP、REST 与静态页面；`Promotion Worker` 作为同一进程内的定时任务（可独立进程化）。

## 3. 技术选型

| 层 | 选型 | 版本 | 理由 | 备选 |
|---|---|---|---|---|
| 运行时 | Node.js + TypeScript | 22 LTS / TS 5.x | MCP TS SDK 为参考实现；前后端同栈 | Python 3.11 + FastAPI + FastMCP |
| MCP | `@modelcontextprotocol/sdk` 的 `StreamableHTTPServerTransport` | 最新 | 当前规范的 HTTP 传输，单端点 + 会话头 | 旧 HTTP+SSE（已废弃，不采用） |
| HTTP 框架 | Fastify | 5.x | 低开销、schema 校验内建、插件模型清晰 | Hono / Express |
| 数据库 | PostgreSQL | 16+ | 事务、JSONB、数组、分区、扩展生态 | — |
| 向量 | pgvector（**可选，暂未启用**） | 0.8+ | 与主库同事务，避免第二套系统；当前召回不依赖它，见 §12 D2 | Qdrant（规模更大时） |
| 中文分词 | `@node-rs/jieba` | 最新 | 应用层切词，存 `text[]` + GIN，免编译 PG 扩展 | pg_jieba / zhparser（需编译，升级成本高） |
| SQL 访问 | `postgres`（porsager） | 3.x | 裸 SQL，递归 CTE 与批量写入可控 | Drizzle（仅用于迁移） |
| 图谱渲染 | AntV G6（Vue 组件内集成）+ cluster 聚类视图 | 5.x | 需求方指定；内置 combo/聚类布局，5k 节点内交互成熟 | Sigma.js（WebGL，超大图） |
| 前端 | Vue 3 + Vite + TanStack Query (Vue) | 3.x | 组合式 API + 响应式状态；构建产物由同一服务托管 | React |
| UI | shadcn-vue + Tailwind CSS | Tailwind 4.x | 需求方指定；可复制组件 + CSS 变量主题，配 `@tailwindcss/vite` 无需额外构建配置 | Naive UI / Element Plus |
| 部署 | Docker Compose | — | app + postgres 两个容器 | — |

**不引入 ORM 的理由**：核心查询是递归 CTE、数组交叠、加权排序、分区裁剪，ORM 生成的 SQL 通常需要退化到 raw query，反而多一层维护成本。迁移用编号 `.sql` 文件。

**不编译 pg_jieba 的理由**：应用层本来就要拿分词结果做 term 归一与别名合并，重复一次没有收益；且 PG 大版本升级时不必重装扩展。

## 4. 数据模型

### 4.1 关系总览

```
app_user ──┬─< mem_block        (L1，按 label 分四类)
           ├─< term ──< term_edge (词图，自关联多对多)
           ├─< mem_event ──1:1── mem_card (L2)
           │                        ├─< card_term  >── term   (多对多倒排)
           │                        └─< card_raw   >── mem_raw (多对多)
           ├─< mem_raw           (L3，按月分区，只追加)
           ├─< promotion_candidate
           └─< mem_audit
```

关键点：`card_raw` 与 `card_term` 都是**连接表**，多对多在此落地；`term_edge` 让词与词之间也能多对多关联，构成"无限关联"的图。

### 4.2 表定义（DDL 摘要）

> 与当前迁移的差异：`vector` 扩展**不是必需项**，迁移里用条件 DO 块包住（有扩展才加 `mem_card.embedding` 与 hnsw 索引），没装扩展也能跑；`pg_trgm` 为必需。本节 DDL 为摘要，以 `migrations/` 为准。

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;   -- 必需；vector 为可选，见上

CREATE TABLE app_user (
  id           bigserial PRIMARY KEY,
  external_id  text NOT NULL UNIQUE,
  display_name text,
  created_at   timestamptz NOT NULL DEFAULT now()
);

-- L1 常驻块：persona / rules / skills
CREATE TABLE mem_block (
  id         bigserial PRIMARY KEY,
  user_id    bigint NOT NULL REFERENCES app_user(id) ON DELETE CASCADE,
  label      text NOT NULL CHECK (label IN ('persona','rules','skills')),
  slot       text NOT NULL DEFAULT 'default',
  -- skills/skill:<term_id>：summary 是一句话描述（≤60），content 是详细描述（默认 ≤4000，SKILL_DETAIL_MAX_CHARS 可调）
  summary    text,
  content    text NOT NULL DEFAULT '',
  use_count  int  NOT NULL DEFAULT 0,   -- 被 memory.expand{block_id} 取用的次数
  char_limit int  NOT NULL DEFAULT 2000,
  read_only  boolean NOT NULL DEFAULT false,
  source     text NOT NULL DEFAULT 'human' CHECK (source IN ('human','promoted','agent')),  -- 002 迁移加入 agent
  version    int  NOT NULL DEFAULT 1,
  updated_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (user_id, label, slot),
  CHECK (char_length(content) <= char_limit),
  CHECK (summary IS NULL OR char_length(summary) BETWEEN 1 AND 200)   -- 硬上限落在数据库层
);

-- 词节点
CREATE TABLE term (
  id         bigserial PRIMARY KEY,
  user_id    bigint NOT NULL REFERENCES app_user(id) ON DELETE CASCADE,
  name       text NOT NULL,
  kind       text NOT NULL CHECK (kind IN ('entity','intent','concept')),
  aliases    text[] NOT NULL DEFAULT '{}',
  df         int NOT NULL DEFAULT 0,
  heat       real NOT NULL DEFAULT 0,
  heat_at    timestamptz NOT NULL DEFAULT now(),
  last_hit_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now(),
  deleted_at timestamptz
);
CREATE UNIQUE INDEX term_name_uniq ON term (user_id, lower(name)) WHERE deleted_at IS NULL;
CREATE INDEX term_aliases_gin ON term USING gin (aliases);
CREATE INDEX term_name_trgm  ON term USING gin (lower(name) gin_trgm_ops);

-- 词间边（图的边表）
CREATE TABLE term_edge (
  src_id     bigint NOT NULL REFERENCES term(id) ON DELETE CASCADE,
  dst_id     bigint NOT NULL REFERENCES term(id) ON DELETE CASCADE,
  type       text NOT NULL CHECK (type IN ('co_occur','isa','alias','related')),
  weight     real NOT NULL DEFAULT 1.0 CHECK (weight > 0),
  updated_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (src_id, dst_id, type),
  CHECK (src_id <> dst_id)
);
CREATE INDEX term_edge_dst ON term_edge (dst_id);

-- type='alias'：由 term.aliases 与另一 term.name 互相命中时自动维护（双向，初始权 0.4，
-- 冲突取 GREATEST 不累加）；召回时命中种子沿它一跳扩展（权重 ×0.6，每种子 ≤3 个），
-- 进 PPR 时再 ×0.5——同义只说明"说法不同"，不该压过真实共现。
-- 合并（mergeTermInto）后两节点并一，故合并本身不产生 alias 边。

-- 注入快照（003 迁移）：memory.inspect 的数据源，每用户保留最近 50 条
CREATE TABLE mem_injection (
  id            bigserial PRIMARY KEY,
  user_id       bigint NOT NULL REFERENCES app_user(id) ON DELETE CASCADE,
  query         text NOT NULL,
  scope         text NOT NULL DEFAULT 'all',
  budget_limit  int  NOT NULL,
  budget_used   int  NOT NULL,
  truncated     boolean NOT NULL DEFAULT false,
  blocks        jsonb NOT NULL DEFAULT '[]'::jsonb,
  cards         jsonb NOT NULL DEFAULT '[]'::jsonb,
  hints         jsonb NOT NULL DEFAULT '[]'::jsonb,
  dropped       jsonb NOT NULL DEFAULT '[]'::jsonb,
  dropped_count int NOT NULL DEFAULT 0,
  elapsed_ms    int,
  created_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX mem_injection_recent ON mem_injection (user_id, id DESC);

CREATE TABLE mem_event (
  id         bigserial PRIMARY KEY,
  user_id    bigint NOT NULL REFERENCES app_user(id) ON DELETE CASCADE,
  session_id text,
  title      text,
  status     text NOT NULL DEFAULT 'open' CHECK (status IN ('open','closed','archived')),
  started_at timestamptz NOT NULL DEFAULT now(),
  ended_at   timestamptz
);
CREATE INDEX mem_event_user_time ON mem_event (user_id, started_at DESC);

-- L2 事件卡
CREATE TABLE mem_card (
  id           bigserial PRIMARY KEY,
  event_id     bigint NOT NULL UNIQUE REFERENCES mem_event(id) ON DELETE CASCADE,
  user_id      bigint NOT NULL REFERENCES app_user(id) ON DELETE CASCADE,
  summary      text NOT NULL,
  intent       text,
  keywords     text[] NOT NULL DEFAULT '{}',
  entities     text[] NOT NULL DEFAULT '{}',
  status       text NOT NULL DEFAULT 'ready',
  source       text NOT NULL DEFAULT 'user' CHECK (source IN ('user','external','system')),
  category     text NOT NULL DEFAULT 'general' CHECK (category IN ('general','person')),
  importance   real NOT NULL DEFAULT 0.5,
  confidence   real NOT NULL DEFAULT 0.8,
  use_count    int  NOT NULL DEFAULT 0,
  heat         real NOT NULL DEFAULT 0,
  heat_at      timestamptz NOT NULL DEFAULT now(),
  last_used_at timestamptz,
  last_hit_at  timestamptz,
  stale_at     timestamptz,
  is_skeleton  boolean NOT NULL DEFAULT false,
  skeleton_at  timestamptz,
  pinned       boolean NOT NULL DEFAULT false,
  version      int  NOT NULL DEFAULT 1,
  -- embedding vector(1024)：仅当安装了 pgvector 时由条件迁移添加，默认不存在
  created_at   timestamptz NOT NULL DEFAULT now(),
  updated_at   timestamptz NOT NULL DEFAULT now(),
  deleted_at   timestamptz,
  -- 库层上限 600 兼容历史；服务层写入/更正/滚动合并统一按 40–200 管控
  CHECK (char_length(summary) BETWEEN 40 AND 600)
);
CREATE INDEX mem_card_kw   ON mem_card USING gin (keywords);
CREATE INDEX mem_card_ent  ON mem_card USING gin (entities);
CREATE INDEX mem_card_time ON mem_card (user_id, created_at DESC) WHERE deleted_at IS NULL;
CREATE INDEX mem_card_heat ON mem_card (user_id, heat DESC) WHERE deleted_at IS NULL;
-- mem_card_emb（hnsw / vector_cosine_ops）同样只在装了 pgvector 时创建

-- 倒排：卡 ↔ 词（多对多）
CREATE TABLE card_term (
  card_id bigint NOT NULL REFERENCES mem_card(id) ON DELETE CASCADE,
  term_id bigint NOT NULL REFERENCES term(id) ON DELETE CASCADE,
  role    text NOT NULL DEFAULT 'keyword' CHECK (role IN ('subject','intent','keyword','entity')),
  weight  real NOT NULL DEFAULT 1.0,
  PRIMARY KEY (card_id, term_id, role)
);
CREATE INDEX card_term_term ON card_term (term_id, weight DESC);

-- L3 明细（按月分区，只追加）
CREATE TABLE mem_raw (
  id        bigserial,
  event_id  bigint NOT NULL,
  user_id   bigint NOT NULL,
  seq       int  NOT NULL,
  role      text NOT NULL,
  content   text NOT NULL,
  tool_name text,
  ts        timestamptz NOT NULL DEFAULT now(),
  hash      bytea,
  PRIMARY KEY (id, ts)
) PARTITION BY RANGE (ts);
-- 每月由迁移/定时任务创建：mem_raw_2026_11 PARTITION OF mem_raw FOR VALUES FROM ...

-- 卡 ↔ 原文（多对多，L2→L3 落点）
CREATE TABLE card_raw (
  card_id bigint NOT NULL REFERENCES mem_card(id) ON DELETE CASCADE,
  raw_id  bigint NOT NULL,
  weight  real NOT NULL DEFAULT 1.0,
  PRIMARY KEY (card_id, raw_id)
);

-- 晋升候选（人工确认队列）
CREATE TABLE promotion_candidate (
  id          bigserial PRIMARY KEY,
  user_id     bigint NOT NULL,
  kind        text NOT NULL CHECK (kind IN ('skill','rule','alias','merge','block')),  -- 002 迁移加入 block
  payload     jsonb NOT NULL,
  evidence    bigint[] NOT NULL,
  score       real NOT NULL DEFAULT 0,
  status      text NOT NULL DEFAULT 'pending' CHECK (status IN ('pending','approved','rejected')),
  created_at  timestamptz NOT NULL DEFAULT now(),
  reviewed_at timestamptz
);

-- 审计
CREATE TABLE mem_audit (
  id          bigserial PRIMARY KEY,
  object_type text NOT NULL,
  object_id   bigint NOT NULL,
  op          text NOT NULL,
  before      jsonb,
  after       jsonb,
  actor       text NOT NULL,
  reason      text,
  created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX mem_audit_obj ON mem_audit (object_type, object_id, created_at DESC);
```

### 4.3 三处刻意的设计

1. **硬上限下沉到 CHECK 约束**：`mem_block` 的字符上限、`mem_card` 的摘要长度都由数据库拒绝越界写入。应用层校验会被绕过（脚本、迁移、并发），CHECK 不会。
2. **`mem_raw` 分区主键包含 `ts`**：PostgreSQL 要求分区表主键含分区键。因此 `card_raw.raw_id` 无法建外键，由应用层保证引用完整性——这是分区换来的代价，需在代码评审中明确。
3. **`term.df` 冗余计数**：用于剪枝判断（`df < 2` 的词不参与扩散）和图谱首屏排序，避免每次聚合全表。

### 4.4 索引与查询路径对应表

| 查询 | 走哪个索引 | 目标延迟 |
|---|---|---|
| 按词取卡（一跳） | `card_term_term` | < 5ms |
| 按别名找词 | `term_aliases_gin` | < 10ms |
| 词名模糊匹配 | `term_name_trgm` | < 20ms |
| 时间范围筛卡 | `mem_card_time` | < 10ms |
| 向量兜底召回（**预留，未启用**） | `mem_card_emb` (HNSW) | — |
| 原文按事件取回 | 分区裁剪 + `PRIMARY KEY` | < 5ms |

### 4.5 何时需要换图数据库（预设出口）

触发条件（满足任一即评估）：

- 常需要 **4 跳以上**路径查询；
- 需要在库内跑**图算法**（社区发现、中心度、全图 PPR）；
- 需要**毫秒级交互式全图可视化**（> 2 万节点）。

切换方式：`MemoryService.graph` 抽象为 `GraphStore` 接口（`neighbors` / `walk` / `ppr`），当前实现基于 SQL；届时替换为 Cypher 实现，`term` / `term_edge` 作为真相源异步同步过去。**不做双写**，图库是派生的读模型。

## 5. 核心流程

### 5.1 写入路径

```
0) 定位事件：传了 event_id → 校验归属；没传 → 找同 scope 下最近一个
   "未成卡 + 30 分钟内"的 open 事件续写（返回 resumed=true），找不到才新建；
   new_event=true 可强制新建。
   目的：轮次阈值按"事件内原文条数"计，若每轮单条写入都新建事件，
   这些事件永远达不到阈值、永远不成卡，等于写进黑洞。
对话轮次 → 写入 mem_raw(seq++) →
  若 事件结束 / 轮次≥N / 用户显式结束：
    0) 追加判定：调用方（AI）结合 recall / memory.cards 决定是否传 append_to
       → 传了：内容并入该卡（关键词/实体并集、原文挂同卡、热度+2.0）
         摘要策略：summary_mode=append（默认，原结论 + 最新追加滚动）| replace（用本次摘要覆盖）
       → 没传：新建卡；服务端默认不做相似度合并（dedupe=true 才启用兜底）
    1) 取卡字段：摘要(120-200字) + intent + keywords(建议 1-3，浓缩全篇的关键性词语；文字约束不硬拦) + entities
       ① 调用方（Agent）经 MCP memory.write 的 card 参数传入 → 直接用（仅校验长度/去重）
       ② 未传的字段 → 本地规则兜底（词频 + 句式 + 实体正则），服务端无模型调用
    2) 写 mem_card（version=1）
    3) 切词 → upsert term → 写 card_term
    4) 同卡内词两两计共现 → upsert term_edge(co_occur, weight+=1)
    5) 更新 term.df
    6) 维护同义边：aliases 与其它 term.name 互相命中 → 双向 alias 边（低权、不累加）
    （embedding 未实现：见 §12 D2；当前召回只依赖关键词倒排 + 词图）
```

约束：**成卡失败不得阻塞对话**。失败时卡保持 `pending` 状态，由 Worker 重试（指数退避，上限 5 次），超过上限转人工队列。

### 5.2 召回路径（核心）

```
recall(query, budget=2200):
  L1  := 读 mem_block 全部四类
  L1.5:= 读最近 15 条事件索引（id + 关键词）
  seeds := extractTerms(query)             // 词典精确匹配 + 分词兜底，2–4 个（本地）
  seeds += aliasFanout(seeds)              // 一跳同义扩展：权重 ×0.6，每种子 ≤3 个
  sub  := buildSubgraph(seeds, hops=2, cap=5000)   // 只取出局部子图
  ppr  := personalizedPageRank(sub, seeds, d=0.85, iter=20)
  terms:= topK(ppr, 20) 且 df ≥ 2
  cards:= 倒排取卡(terms) → 打分排序 → top 60
  strong := cards 中满足强关联条件者
  weak   := 其余中取 top 3，仅生成提示行
  result := pack(L1, L1.5, strong, weak, budget)
  saveSnapshot(result)                     // mem_injection：供 memory.inspect 回看
  return result
```

`pack()` 按 `score / token` 贪心装填，装不下就停在预算处，并记录 `dropped` 明细。

补充约束：

- **整块保留或整块丢弃**：L1 块、事件卡、L1.5 索引都不做半句截断；确需截断时只在 `。！？；` 边界切，切不出整句则整块丢弃，并由 `truncated: true` 标记本次注入不完整。
- **hints 与 cards 互斥**：已进入 `cards` 的卡不会再出现在提示行。
- **空召回兜底**：种子词为空时不再静默返回，`note` 说明"未命中实词"，并附最多 3 条最近记录作为提示。
- **摘要长度统一**：库层 CHECK 为 40–600（兼容历史），服务层写入、更正、滚动合并统一按 **40–200** 管控；追加合并采用"原结论 + 最新一次追加"的滚动策略，不再无限拼接。
- **调试开关**：`debug=false`（默认）不返回 `trace` / `injection_order` / `dropped` 明细，只给 `dropped_count` 与 `truncated`。
- **注入快照**：每次召回落一条 `mem_injection`（blocks/cards/hints/dropped + 预算 + 耗时），`memory.inspect` 只读回看；回看不重新召回、不动热度信号（重跑 recall 会把命中热度 +1，反而污染观测）。每用户保留最近 50 条。
- **裁剪原因分档**：`budget`（预算装不下）/ `truncated-to-zero`（找不到句末边界）/ `cold`（冷记忆）/ `weak_trimmed`（超出 `WEAK_HINT_LIMIT`）/ `df_filtered`（df<2 不参与扩散）/ `limit_truncated`（候选或入选条数上限）。词侧截断按 `count` 聚合，避免一次刷几十行。
- **经验只注入索引**：`skills/skill:<term_id>` 的正文不进上下文，只按热度取前 `SKILL_INDEX_LIMIT`（默认 5）条索引行——`#block_id + 一句话描述 + 调用次数`。命中后由 `expand{block_id}` 取回 `summary + content`，此时才 `use_count +1` 并累加热度；只"看到索引"不计数。

### 5.3 打分公式

```
score = 0.45 * ppr_norm
      + 0.25 * exp(-ln2 * age_days / 30)        // 半衰期 30 天
      + 0.15 * log(1 + use_count) / log(1 + 50)
      + 0.15 * importance
```

强关联判定（三条同时满足）：

- `ppr_norm ≥ 0.30`
- `age_days ≤ 30`
- 与查询的 term 重合数 `≥ 2`

否则为弱关联，仅输出提示行。

### 5.4 晋升流程

| 阶段 | 触发 | 动作 | 人工介入 |
|---|---|---|---|
| L3 → L2 | 事件关闭 | 采用调用方 `card` 字段成卡，缺字段由规则补齐 | 无 |
| L2 → L1 | **调用方经 MCP `memory.correct` 写入** | 写 `mem_block(label='skills', slot='skill:<term_id>', source='agent')`：`summary` 一句话描述 ≤60 字、`content` 详细描述默认 ≤4000 字（`SKILL_DETAIL_MAX_CHARS` 可调），带来源指针；L1 只取热度前 5 条索引 | 视 `BLOCK_APPROVAL_LABELS` |
| L1 下线 | 90 天未使用或超预算 | 软删，来源卡保留；重新写入需调用方再写 | 无 |

服务端不按热度或事件数自动生成经验条，也不生成 skill 候选。

反污染规则：不再有任何自动晋升；三类块都只由 MCP 调用方写入。审核名单由 `BLOCK_APPROVAL_LABELS` 配置，默认留空即全部直写；名单包含 `persona` / `rules` 时，非人工写入落 `promotion_candidate(kind='block')`，返回 `pending_approval`，人工批准后才写 `mem_block`（`source='agent'`）。

### 5.5 失效传播

实体节点（`term.kind='entity'`）被合并或重命名时：

1. 找出引用该词的卡：`SELECT card_id FROM card_term WHERE term_id = ?`
2. 批量置 `stale_at = now()`
3. 下次召回命中 `stale` 卡时，先触发一次重算（同步或降级为返回旧值 + 标记）

## 7. Web 管理端设计

四个页面：

1. **记忆列表**：左筛选（term / intent / 时间 / 状态），右列表；支持"只看 stale"。
2. **详情抽屉**：编辑摘要与标签，下方列出引用的 L3 原文（可展开）；底部显示版本历史。
3. **图谱视图**：AntV G6（Vue 3 组件内集成）的**径向力导向图**，链路为 根节点 → 关键词 → 记忆卡片。
   - **层级结构**：根节点 `l1:root`（L1 常驻）居中，关键词内环、事件卡外环；节点全部为圆形，文字绘在圆内。颜色：L1 紫、关键词 琥珀、L2 蓝。L3 原文不进图。
   - **关键词过滤**：`GET /api/graph/radial?min_cards=3&heat_top=0` 只返回「出现的记忆卡数 ≥ N」的关键词（N 页面可设，默认 3），再按热度取前 K（可选）；未命中任何显示词的卡挂到「其他」词节点，不丢卡且链路仍是 根→词→卡。
   - **同心环**：官方 `concentric` 布局，`sortBy` 按节点类型分三环（值越大越靠中心），每层按 `2π/N` 均分整圈，`preventOverlap + nodeSize + nodeSpacing` 自动算环半径；不用树型 radial（父子扇区会把大量卡片挤成一段圆弧）；节点可拖拽、画布可缩放。
   - **关键词联动**：悬停或选中某个关键词，高亮提及它的记忆卡与共现词，其余节点淡出；根节点选中无效。
   - **联想边**：L1→词为 `holds`（标注"命中卡数"）；词→卡为 `mentions`；同卡内词之间的共现为 `co_occur`（虚线，体现"关键词互相连接"）。
   - **展示细节**：同层按热度排序后换行铺开，层间留白；节点大小映射热度（L1 最大、L3 最小）；右侧面板给出层级计数、选中节点的摘要/关键词/原文与"展开下一层"。
   - **性能护栏**：单次展开每类 ≤20 条（`truncated` 标记），前端节点总量 ≤700，超出提示先重置；「展开 L2 / 展开关键词 / 展开 L3」按钮可批量下钻。
   - 兼容保留：`GET /api/graph`（按连通分量聚簇 + 词图）仍可用，供只关心词间关系的场景。
4. **待审队列**：卡片列表展示候选经验、证据卡链接、批准 / 驳回按钮。

交互要求：任何删除操作先进回收站，7 天内可恢复；物理清除需输入确认短语。

## 8. 性能与容量

### 8.1 容量基线

| 对象 | 首版目标 | 上限测算 |
|---|---|---|
| 事件卡 | 100 万 | 每卡约 1KB（启用向量后再 +4KB，当前未启用） |
| 词间边 | 1000 万 | 每行约 40B → 约 400MB |
| term | 10 万 | — |
| L3 原文 | 5000 万行 | 按月分区，冷月可 detach 归档 |

### 8.2 PPR 的工程约束

全图 PPR 不可行：1000 万边 × 20 次迭代 ≈ 2 亿次操作，Node 单线程需 1–2 秒。

**做法**：先抽局部子图（种子 2 跳、节点上限 5000、边上限 5 万），在子图上跑 PPR。子图规模下迭代 20 次约 5–15ms。

子图抽取用一条递归 CTE 完成，`LIMIT` 在每一层生效（`depth ≤ 2`），避免度数爆炸：

```sql
WITH RECURSIVE sub(id, depth) AS (
  SELECT id, 0 FROM term WHERE name = ANY($1) AND deleted_at IS NULL
  UNION
  SELECT e.dst_id, s.depth + 1
  FROM sub s JOIN term_edge e ON e.src_id = s.id
  WHERE s.depth < 2
)
SELECT id FROM sub LIMIT 5000;
```

### 8.3 延迟预算（recall 端到端 P95 < 300ms）

| 步骤 | 预算 |
|---|---|
| term 抽取（词典命中） | 5ms |
| term 抽取（分词兜底） | 5ms（本地，无网络调用） |
| 子图抽取 | 20ms |
| PPR（5000 节点） | 15ms |
| 倒排取卡 + 打分 | 30ms |
| 同义 fan-out（一次 alias 边查询） | 3ms |
| 打包与序列化 | 10ms |
| 注入快照写入（含保留策略清理） | 5ms |

服务端不含任何模型调用：抽取全在本地（词典 + jieba），因此端到端延迟可预估、无外部超时风险。

## 9. 安全与隐私

1. **鉴权**：HTTP MCP 与 REST 全部走 `Authorization: Bearer <token>`；token 存环境变量，首版单 token，多用户时升级为用户表 + 哈希存储。
2. **来源校验**：校验 `Origin` 白名单，默认只允许同源与 `localhost`；关闭通配 CORS。
3. **注入防护**：外部内容（网页、文档、工具返回）写入时必须标 `source='external'`，只能进 L2。服务端**没有任何自动晋升路径**——L1 只能由调用方经 `memory.correct` 写入——因此不存在"外部内容自动固化"的通道；`source` 字段在 recall 的 `cards[].source` 上显式回传，调用方据此核实后才可写入 L1。这是防"记忆投毒"的闸门。
4. **删除语义**：软删置 `deleted_at`，所有查询默认过滤；`purge` 才物理删除并写审计（记录删除者与时间，不保留内容）。
5. **隐私**：默认不外传原文；服务端不调用任何模型，语义字段（摘要/意图/关键词/实体）由调用方经 MCP 传入或本地规则生成，原文不出环境。

## 10. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 图爆炸 | term 与边数失控，查询变慢 | `df < 2` 不建节点；边只保留 top-k 共现；每周剪枝任务 |
| 同义词碎片 | "股票/股市/A股"各成一节点，联想断裂 | 别名表 + 写入时归并 + 定期合并任务 + Web 端手动 merge |
| 联想跑偏 | 用户问 A，系统扯到三个月前的 B | 强/弱关联分级；弱关联只给提示行；提示可关闭 |
| 记忆污染 | 模型自己编的规则被固化为 L1 | 无自动晋升路径（L1 只能由调用方写）；`rules`/`persona` 的模型写入默认进人工审核队列；外部内容标 `source='external'` 并在 recall 中显式回传 |
| 浓缩丢信息 | 摘要过于抽象，下钻时找不到原文 | 卡必须持有 `card_raw` 引用；浓缩 prompt 强制输出"可回指的锚点" |
| 中文分词错误 | "选哪个好"被切碎，分支合并错乱 | 短语优先：先匹配现有 term 词典，未命中再交给分词器；新词进候选队列 |
| 前缀缓存失效 | L1 每轮变化导致成本上升 | L1.5 独立，置于 prompt 末尾；L1 仅在人工确认后变化 |

## 附录 A：两条关键 SQL

**A.1 两跳词扩散（带路径去重与时间衰减）**

```sql
WITH RECURSIVE walk(term_id, depth, path, w) AS (
  SELECT id, 0, ARRAY[id], 1.0::real FROM term WHERE name = ANY($1)
  UNION ALL
  SELECT e.dst_id, w.depth + 1, w.path || e.dst_id,
         w.w * e.weight * exp(-0.05 * EXTRACT(EPOCH FROM (now() - e.updated_at)) / 86400)
  FROM walk w JOIN term_edge e ON e.src_id = w.term_id
  WHERE w.depth < 3 AND NOT e.dst_id = ANY(w.path)
)
SELECT term_id, max(w) AS score FROM walk GROUP BY term_id ORDER BY score DESC LIMIT 50;
```

**A.2 倒排取卡并打分**

```sql
SELECT c.id, c.summary, c.keywords,
       sum(ct.weight * t.score)                                   AS ppr_score,
       exp(-ln(2) * EXTRACT(EPOCH FROM (now() - c.created_at)) / 86400 / 30) AS recency,
       c.importance, c.use_count
FROM card_term ct
JOIN mem_card c ON c.id = ct.card_id AND c.deleted_at IS NULL
JOIN (SELECT term_id, max(w) AS score FROM walk GROUP BY term_id) t ON t.term_id = ct.term_id
GROUP BY c.id
ORDER BY (0.45 * sum(ct.weight * t.score) + 0.25 * recency + 0.15 * c.importance) DESC
LIMIT 60;
```
