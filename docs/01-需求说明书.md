## 1. 概述

MemLattice 是给 AI Agent 用的长期记忆库。它要解决一件事：**让模型跨会话记住一个人，且成本不随对话轮次增长。**

四条机制构成整体：

1. **分层**——记忆按抽象度与变化频率分为 L1 常驻、L1.5 滚动、L2 事件卡、L3 明细四层，检索先读高层、按需下钻。
2. **联想**——关键词以「入口词 × 意图」建索引，同一入口词下的多条历史分支并列共存，可多跳扩散。
3. **固化**——记忆被反复使用则热度上升，达阈值自动升入 L1 形成精简条目，并保留指向来源的指针。
4. **淡忘**——长期不被触及的记忆逐级降级，细节先失、结论后留，最终归档。

数据落在单一 PostgreSQL，通过 MCP 提供给 Agent，通过 Web 供人查看、编辑与删除。

### 1.1 问题

- 大模型无状态，"记得"只有两条路：重放历史（成本线性增长、有窗口上限、长上下文召回率下降），或落到外部系统按需取回。
- 现有方案各有缺口：分层抽象派（TencentDB-Agent-Memory、OpenViking）有预算控制但缺联想；图谱派（Graphiti、Neo4j Agent Memory）有关系结构但缺稳定常驻层与硬预算；通用记忆层（Mem0）以向量为主，撑不起"同一入口词的多分支历史"。
- 热度、固化、淡忘这三个机制在现有开源项目中均无完整实现。

### 1.2 非目标

不做通用文档问答、多租户计费、多模态记忆、多人实时协同、跨地域容灾、模型训练。

## 2. 目标与验收

| 编号 | 目标 | 验收方式 | 通过条件 |
|---|---|---|---|
| G1 | 常驻成本可控 | 统计 100 次真实 recall 的注入量 | 平均 ≤1000 token，峰值 ≤1200 |
| G2 | 跨会话可联想 | 自建 50 条"同入口词多分支"评测集 | Recall@5 ≥ 0.8 |
| G3 | 记忆可治理 | 人工走查 20 条记忆的定位与编辑 | 平均点击数 ≤3 |
| G4 | 写入可回溯 | 抽查 10 次修改 | 审计完整率 100% |
| G5 | 接口标准化 | 用官方 MCP 客户端接入 | 10 个工具均可调用（含 4 个只读：`cards` / `pending` / `inspect` / `start`） |
| G6 | 记忆自动分层 | 抓取 50 次 recall 前 5 条，比对热度分位 | 热度前 20% 占比 ≥80% |
| G7 | 记忆具备生命周期 | 连续运行 30 天后统计 L1 条目来源 | 经验条 100% 由调用方经 MCP 写入，服务端不自动生成 |

## 3. 角色与场景

| 角色 | 说明 | 入口 |
|---|---|---|
| 记忆主体 | 被记忆的人，通常即使用者 | 间接 |
| 调用方 | AI Agent | MCP（HTTP / stdio） |
| 管理者 | 主体本人，负责审阅纠错 | Web 管理端 |

| 编号 | 场景 | 期望行为 |
|---|---|---|
| S1 | 日常对话 | 每轮写入 L3；事件结束自动浓缩为一张 L2 卡 |
| S2 | 跨会话联想 | 问"今天股票行情"时，提示"你此前问过股票选哪个好"，由用户决定是否展开 |
| S3 | 纠错 | Web 端改卡或删卡，后续不再召回旧内容 |
| S4 | 遗忘 | 区分"不再召回"（软删）与"物理清除"（不可恢复） |
| S5 | 审计 | 可查某条记忆的来源原文与生成时间 |

## 4. 术语

| 术语 | 定义 |
|---|---|
| L1 常驻层 | 始终注入的高密度记忆块：性格、规则、经验 |
| L1.5 滚动层 | 最近若干事件的关键词索引，只含事件 ID 与关键词，每轮可变 |
| L2 事件卡 | 单事件浓缩记忆，只留结论、意图、关键词与实体，不含细节 |
| L3 明细层 | 原始对话、工具调用与结果，只追加，按 ID 精确取回 |
| 事件 | 一次有始有终的交互单元，可跨多轮 |
| term / intent | 索引词节点（实体/意图/概念）/ 事件诉求类型（查状态、求推荐、排错） |
| 热度 | 访问行为的加权累计经时间指数衰减后的值，用于排序与生命周期决策 |
| 固化 | 热度达阈值的经验自动写成 L1 精简条目并携带来源指针的过程 |
| 淡忘 | 冷记忆逐级降级、细节先失后留的过程 |
| 骨架卡 | 淡忘后的 L2 形态，只留结论与关键词，不再持有原文引用 |
| 强/弱关联 | 可直接注入上下文 / 仅以提示行呈现且不占预算 |
| 预算 | 单次召回允许注入的 token 上限，超限必须裁剪 |

## 5. 功能需求

优先级：**P0** 首版必交付，**P1** 可延后一个迭代。

> 编号说明：FR-01～FR-16 为初版范围；FR-17（注入可观测）、FR-18（写入兜口）为试用后新增，按功能域插入各自小节，编号不连续属正常。

### 5.1 分层存储

**FR-01 L1 常驻块（P0）**
- 三类块：`persona`（性格与表达风格）、`rules`（硬规则）、`skills`（经验，形式为 `条件→动作`）。
- 每块设字符上限，超限写入失败并明确报错，不得静默截断；每次修改留版本。
- `rules` 不得由系统自动生成或修改。
- 验收：超限返回 `E_BLOCK_LIMIT`；对 `rules` 的自动写入被拒绝。

**FR-02 L1.5 滚动索引（P0）**
- 只存 `event_id` + ≤3 个关键词，不含任何摘要正文。
- 上限 15 条、TTL 7 天，超限或过期自动淘汰。
- 每轮可变，须置于 prompt 末尾，避免破坏前缀缓存。
- 验收：条数不超上限；过期事件消失；该层不含原文片段。

**FR-03 L2 事件卡（P0）**
- 一事件一卡，摘要 120–200 字，**不得包含原文细节**。
- 必填：摘要、意图、关键词（1–3，浓缩全篇的关键性词语：主题词/实体/核心概念，禁口语碎片与虚词）、实体、状态、时间范围、重要度。
- 卡可引用 1..N 条 L3，一条 L3 可被多卡引用（多对多）。
- 支持 `stale` 标记，命中时先重算再返回；支持骨架卡形态（见 FR-16）。
- 验收：摘要长度受约束；删卡不影响其引用的原文；骨架卡不返回原文引用。

**FR-04 L3 明细层（P0）**
- 只追加，不允许修改或删除单条；更正以新增记录表达。
- 按 `event_id` + 序号精确取回。
- 保留 12 个月后归档，归档后仍可按 ID 取回（延迟可放宽）。
- 验收：更新已写入记录被拒；取回内容与写入一致。

### 5.2 联想索引

**FR-05 关键词图（P0）**
- term 支持新增、合并、别名维护；同义词（股票 / 股市 / A股 / 个股）**能合并的合并为同一节点**（默认路径）。
- term 之间可建边，类型含共现、上下位、别名、相关。
- 需要各自保留独立节点的同义词，用双向低权的 `alias` 边声明（由 `aliases` 与另一词 `name` 互相命中时自动建立）；召回时对命中的种子做一跳同义扩展，权重打折——同义能带出上下文，但压不过真实共现。
- 索引键为 **(term, intent) 二维**，"股票→情况"与"股票→哪个好"须作为并列分支共存。
- 从任一 term 可展开一跳，返回相邻词与该词下的事件卡。
- 验收：查"股票"同时返回两个分支；查"股市"命中同一节点；声明同义后，查"股票行情"也能召回只挂"大盘"的卡。

**FR-06 多维挂载（P0）**
- 一条 L2 卡可同时按实体、意图、时间、场景四个维度检索。
- 任一维度不得为必填，但至少一个维度可检索。
- 验收：同一张卡可用三种不同维度分别召回。

### 5.3 召回与下钻

**FR-07 逐层召回与预算（P0）**
- L1 常驻块由 `memory.start` 在会话开始注入一次；`recall()` 默认只注入 L1.5 滚动索引与 L2 强关联卡，不加载 L2 正文、不重复注入 L1。
- L2 候选分两级：强关联直接注入；弱关联只输出一行提示，**不占预算**。
- 单次注入硬上限 1200 token（默认），超限按性价比裁剪并记录丢弃明细。
- 验收：50 张相关卡的场景下总量不超上限；弱关联不出现在正文。

**FR-08 下钻（P0）**
- 支持按 `card_id` 或 `term` 展开一跳，返回下层内容与可继续下钻的 ID。
- 每次下钻携带 L3 原文引用，保证可溯源。
- 验收：从 L1 提示出发，两步内取回对应原文片段。

**FR-17 注入可观测（P0）**
- 每次召回把"实际注入了什么"落库为快照：L1 块（含各自 token）、事件卡、提示行，以及全部被裁剪项与原因。
- 裁剪原因须可区分：预算不足、冷记忆、弱关联超出提示配额、`df` 不足未参与扩散、候选/入选条数上限。
- 只读接口可按 `recall_id` 回看历史快照，默认取最近一次；**回看不重新召回、不改变热度信号**。
- 快照按用户保留最近 50 条，超出自动清理。
- 验收：把预算调小一次，能直接指出被裁的是哪些块、各占多少 token，不需要靠调参重试来猜。

### 5.4 生命周期

**FR-09 晋升（P0）**
- L3 → L2：事件结束或达轮次阈值时自动浓缩。
- L2 → L1 只有一条路径：**调用方经 MCP `memory.correct` 写入**；`persona`/`rules` 可配置人工审核，批准后才生效。
- 写入的 L1 条目均带来源指针，均可在 Web 端撤销。
- 服务端**不做任何自动晋升**（不按热度、不按事件数）。
- 验收：调用方写入后 L1 出现条目且指针可下钻；未写入时巡检不产生条目；撤销后来源卡完好。

**FR-10 降级与失效（P1）**
- L1 经验 90 天未使用，降级回 L2。
- 卡引用的实体变更时，相关卡标 `stale`。
- 一致性优先级固定：**人工规则 > L3 原始事实 > L1 自动推断**；冲突时低优先级让位并写审计。
- 验收：制造规则与推断冲突，结果以规则为准且审计有记录。

**FR-14 热度（P0）**
- term、L2 卡、经验块各维护热度与 `use_count`，由访问行为累加、随时间指数衰减。
- 计数信号只认行为：召回命中 +1.0、展开下钻 +1.5、经验块被按 id 取用 +1.0、被新卡引用 +2.0、人工编辑 +0.5；仅"索引被注入"不计数。
- 半衰期默认：term 14 天、卡 30 天，可按类别覆盖（人物关系类取更长）。
- 排序一律先热后冷：召回结果、Web 列表、图谱首屏同一规则；冷记忆沉底且不进默认预算，仅"展开全部"时返回。
- 热度**不得由模型自行估算或写入**，只能由访问事件驱动。
- 验收：命中多者排序靠前；7 天无访问位次下降；冷记忆不出现在默认 recall；伪造模型自评热度被拒。

**FR-15 固化（P0）**
- 经验条**只由调用方经 MCP 写入**，服务端不按热度或事件数自动生成。
- 一条经验三个字段：`id`（即 `block_id`）、`summary`（一句话描述这个技能干什么用，≤60 字）、`content`（详细描述，默认 ≤4000 字，由 `SKILL_DETAIL_MAX_CHARS` 配置）；另记 `use_count`（被真正取用的次数）。
- 必须携带两类来源指针：来源 term 列表、来源事件卡列表（可下钻）。
- L1 **只注入索引**：按热度取前 5 条，每行只有 `id + 一句话描述 + 调用次数`，不含详细描述；详细描述经只读工具按 `block_id` 现取，**取用时才计一次调用并累加热度**（只是"看到索引"不计数）。
- 条目在 L1 内按热度排序；L1 预算超限时**淘汰最冷条目**回落 L2——L1 本身是容量受限的缓存。
- 可撤销：撤销后回落为 L2 卡，不删除任何来源数据。
- `rules`、`persona`、外部来源内容均不得固化。
- 验收：调用方写入后 L1 出现索引、`id` 可下钻取回完整描述；索引条数 ≤5 且按调用热度排序；巡检运行后条目数不变；超预算时最冷条目被移除；撤销后来源卡完好。

**FR-16 淡忘（P0）**
- 冷判定：热度 <0.5 且连续 90 天未被命中（term）或未被召回（卡）。
- 三级降级，**逐级而非一次销毁**：L1 条目到期移出 → L2 由调用方在整理时压成骨架卡（≤80 字，断开 L3 引用）→ L3 转归档，24 个月后物理清除。
- 原地修改允许，但必须生成新版本并保留压缩快照，不得覆盖到不可恢复。
- 保底规则：`importance ≥0.8`、人工钉住、人物关系类不参与自动淡忘；每年至少保留历史卡 10%。
- 物理清除前先进回收站，7 天内可恢复，动作写审计。
- 验收：90 天未访问的卡进入待淡忘候选；调用方压成骨架后不返回原文；保底池内的卡不受影响；清除后 7 天内可恢复；审计可查压缩前后摘要。

**FR-18 写入兜口（P0）**
- 未显式指定事件时，同一场景内自动续写最近一个"未成卡"的会话事件（默认 30 分钟窗口），避免每轮单条写入产生永远达不到浓缩阈值的事件。
- 需要另起一件事时，可显式要求新建事件（`new_event`），或换场景标识。
- 巡检兜底：超过窗口仍未成卡的事件，内容足够则自动浓缩成卡；内容过少则归档（不删除任何 L3 原文）；浓缩出错进重试队列。
- 验收：连续 5 轮单条写入后只产生 1 张卡；人为中断后巡检能把遗留事件收口，且原文条数不变。

### 5.5 接口与管理

**FR-11 MCP 接口（P0）**
- 同时提供 HTTP（Streamable HTTP，单端点）与 stdio，共享同一业务层。
- 10 个工具，写 4 读 6：
  - 写：`write`、`write.batch`（既有的批量形式）、`correct`、`forget`
  - 读：`start`（会话初始化，L1 唯一注入点）、`recall`（按话题召回卡）、`expand`、`cards`、`pending`、`inspect`
- **L1 常驻块只由 `start` 在新会话开始注入一次**；`recall` 不返回 L1，避免每轮把 L1 重复堆进历史。用户说「初始化记忆」时重新调用 `start` 刷新。
- 工具数量仍是设计约束：**新增工具优先只读**；写入口只在必要时增加，且必须是既有的批量/组合形式——模型选错写工具的代价远高于选错参数。
- 全部需鉴权，未授权返回 401。
- 验收：本地与远程客户端均可完成一次完整读写；无 token 请求被拒；10 个工具均可调用。

**FR-12 Web 管理端（P0）**
- 列表与搜索：按关键词、term、意图、时间筛选，可只看 `stale`。
- 详情编辑：改 L2 卡内容与标签、改 L1 各块。
- 删除：默认软删进回收站，7 天内可恢复；物理清除需二次确认。
- 图谱浏览：径向力导向图（根→关键词→记忆卡片），关键词按「出现卡数 ≥ N（页面可设，默认 3）」与热度过滤；悬停/选中关键词高亮相关记忆卡，根节点选中无效。
- 待审队列：集中处理人工晋升候选。
- 验收：1000 节点图谱首屏 ≤2 秒；删除后回收站可见并可恢复。

**FR-13 版本与审计（P1）**
- 所有修改记录操作者、时间、变更前后内容与原因。
- 可按对象查看完整变更历史。
- 验收：任意一次编辑可查到 before/after。

## 6. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-01 | 性能 | 单跳图查询 P95 <20ms；`recall` 端到端 P95 <300ms（不含 LLM 抽词） |
| NFR-02 | 容量 | 单库 100 万事件卡、1000 万条词间边、10 万 term |
| NFR-03 | 部署 | 单机 `docker compose up` 可完整启动 |
| NFR-04 | 安全 | 写操作需鉴权；传输 TLS；HTTP 端校验 Origin |
| NFR-05 | 隐私 | 默认本地部署，原文不出环境；外部模型调用可整体关闭 |
| NFR-06 | 可维护 | 表结构变更走迁移脚本，可回滚；关键查询留执行计划基线 |
| NFR-07 | 可观测 | 结构化日志、慢查询日志，以及召回命中率、预算使用率、固化通过率三项指标 |
| NFR-08 | 生命周期任务 | 每日一次全量巡检（热度重算、固化、淡忘），100 万卡规模下单次 ≤5 分钟，可中断续跑 |
| NFR-09 | 排序性能 | 按热度排序须走索引，禁止全表排序；热度增量更新，不得定时全表刷新 |
| NFR-10 | 可逆性 | 固化、淡忘、归档三类动作 7 天内可一键回滚，且不丢来源数据 |

## 7. 约束与假设

- 语言以中文为主，须正确处理中文短语（"选哪个好"不得切成单字）。
- 规模假定为单用户或小团队（<50 人），不假设高并发写入。
- 允许调用外部 LLM 完成抽取与浓缩，成本须可估算、可关闭。
